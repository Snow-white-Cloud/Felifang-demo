# ADR-008: Отказ от ORM, использование чистого SQL

**Дата:** 18.06.2026  
**Статус:** Реализовано  
**Автор:** Snow-white-Cloud

## Контекст
Нужно управлять схемой БД и писать запросы с контролем производительности. ORM (например, GORM) скрывает SQL и может генерировать неоптимальные запросы.

## Решение
Использовать чистый SQL через `database/sql` + драйвер `lib/pq`. Запросы пишутся вручную в storage-слое.

## Обоснование
- Сохраняется полный контроль, что позволяет выполнять сложные запросы или их оптимизировать.
- Код предсказуем.
- Нет нового слоя абстракции.

## Альтернативы (рассматривались)
1. **GORM:** скрывает SQL, труднее оптимизировать.
2. **sqlx:** для текущих задач достаточно `database/sql`, однако возможен безболезненный переход на него при необходимости.

## Ожидаемый эффект
- Все запросы пишутся вручную в storage.
- Возможность оптимизировать каждый запрос.
- Нет зависимости от ORM.
