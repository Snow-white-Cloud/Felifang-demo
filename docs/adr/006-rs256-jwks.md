# ADR-006: Использование RS256 + JWKS для JWT

**Дата:** 20.06.2026  
**Статус:** Реализовано  
**Автор:** Snow-white-Cloud

## Контекст
Токены должны быть проверяемыми другими сервисами без обращения к Auth. Использование HS256 (общий секрет) небезопасно: если один сервис скомпрометирован, секрет известен всем.

## Решение
Использовать RS256 (асимметричное подписание). Auth хранит приватный ключ для подписи токенов. Публичный ключ публикуется через эндпоинт `/.well-known/jwks.json`. Другие микросервисы используют публичный ключ для проверки.

## Обоснование
- Приватный ключ не покидает Auth, что повышает безопасность.
- Проверка токена без запроса к Auth повышает производительность Auth.
- Можно добавить новые сервисы, не настраивая секреты.

## Альтернативы (рассматривались)
1. **HS256 (общий секрет):** опасен при утечке, дурной тон.
2. **Симметричное шифрование:** не подходит для микросервисов.

## Ожидаемый эффект
- Auth подписывает токены приватным ключом.
- Иные микросервисы проверяют через витрину публичных ключей.
- JWKS доступен по стандартному эндпоинту.
