# ADR-001: Структура проекта по стандарту

**Дата:** 20.07.2026  
**Статус:** В процессе  
**Автор:** Snow-white-Cloud

## Контекст
Структура проекта перемешанна: папки лежат не на своих местах (публичная для всех микросервисов в Auth), логика не поделена на слои. Это затрудняет навигацию и не соответствует практике Go-сообщества.

Проект растёт: дорабатывается Auth-сервис, планируются другие. Необходимо организовать код так, чтобы:
- было понятно, что за что отвечает;
- можно было легко добавить новый сервис;
- структура была привычной для других Go-разработчиков.

## Решение
Использовать стандартную структуру, рекомендованную проектом [`golang-standards/project-layout`](https://github.com/golang-standards/project-layout):

```
felifang/
├── api/             # OpenAPI/Protobuf-спецификации
├── backend/
│   ├── cmd/         # Точка входа
│   ├── internal/    # Приватный код
│   └── keys/        # Ключи (не в Git)
├── frontend/        # Место для сервиса клиента
├── pkg/             # Общий код для всех сервисов
├── databases/       # SQL-скрипты инициализации
├── env/             # .env-файлы (не в Git)
├── scripts/         # Утилиты
├── deployments/     # Манифесты для деплоя
├── docs/            # Документация
└── build/           # CI/CD-скрипты
```

## Обоснование
1. **Привычность:** большинство Go-разработчиков знают эту структуру.
2. **Разделение:** `cmd/`, `internal/`, `pkg/` имеют чёткое назначение.
3. **Масштабируемость:** легко добавить новый сервис в `backend/` или `frontend/`.
4. **Безопасность:** `internal/` защищает код от случайного импорта извне.
5. **Документированность:** структура описана и поддерживается сообществом.

## Альтернативы (рассматривались)
1. **Плоская структура или монолит:** неудобна для роста и масштабирования.
2. **Каждый сервис в отдельном репозитории:** избыточно для пет-проекта.

## Ожидаемый эффект
- Все сервисы находятся в `backend/` и `frontend/`.
- Общий код расположен в `pkg/`.
- Приватный код каждого сервиса в `internal/`.
- Новый разработчик понимает структуру быстро и без дополнительного стресса.
